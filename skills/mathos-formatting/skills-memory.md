# MathOS Formatting Skill Memory - 2026-06-25

本文记录了在格式化 2024版北师大版初中数学教材过程中发现的问题以及相应的解决措施，以确保未来格式化任务的规范性与通用性。

## 1. 行为规范：严禁在格式化期间临时修改通用脚本
- **问题**：前次运行中，为了使不规范的目录临时通过验证，Agent 违反技能约束，在 `skills/mathos-formatting/scripts/step1_toc_extraction.py` 中加入了硬编码的特定书籍（如“学习印记”）绕过逻辑。
- **措施**：
  - 严格遵守 `SKILL.md` 规则：**禁止在格式化处理期间修改 `skills/` 下 of Python 通用脚本**。
  - 所有对于特定结构或边缘情况的适配，必须通过 **Prompt 调优** 或 **生成更具防御性的 Sandbox 模板代码（在 prompt 中提供）** 来完成。
  - 本次任务中已通过 `git checkout` 彻底回融了对 `step1_toc_extraction.py` 的非规范修改。

## 2. 目录提取边界与内容混淆问题
- **问题**：
  - 书籍第一章的目录项在排版上先于 `## 目录` 标题出现。旧逻辑或模型容易漏掉前面的章节，或者被迫将目录起点局限于 `## 目录` 之后。
  - 目录结束后紧接着正文前导标题（如 `## 学习印记`），由于没有页码，旧版模型容易将它们误包含进目录，导致后续阶段校验报错。
- **措施**：
  - 优化 `step1_toc_detection_prompt.md` 提示词，添加了对目录起点的明确定义（必须从最早的目录标题或小节项开始，即使 `## 目录` 出现在其后）。
  - 添加了明确的终点控制：目录必须结束于最后一个含有页码的有效目录项（如 `/ 198`），禁止包含其后的无页码前导标题（如“学习印记”、附录、后记）。
  - 恢复严格验证器。如果模型仍包含无页码非目录项，会被 `step1_toc_extraction.py` 严格校验器拒绝并抛出 `FormattingError`，逼迫 LLM 在重试中自我修正。

## 3. 拆分标题（Split Headings）与父级上下文新增冲突
- **问题**：
  - 原始 OCR 文本常将标题拆分为两行，如 `## 第一章` 与 `## 丰富的图形世界`。
  - 模板中的后缀匹配逻辑会将第二部分 `## 丰富的图形世界` 强行重写为 `# 第一章丰富的图形世界`。由于增加了 `"第一章"` 文本，这违反了“不得新增不存在的父级/章节上下文”的严格校验规则，导致 Step 3 验证失败。
- **措施**：
  - 在 `step3_heading_processor_prompt.md` 的 Python 生成模板中，集成了 `adds_parent_context` 校验逻辑。如果重写操作会向标题添加新检测到的父级章节前缀（由 `PARENT_CONTEXT_RE` 等正则匹配），则该匹配直接被拒，防止脚本污染标题。
  - 优化了前瞻逻辑：当前行判定为前缀（如 `第一章`），且下一个标题行正是拆分标题的剩余部分（如 `丰富的图形世界`）时，前缀匹配直接在第一部分重写出完整标题，第二部分则自然落入 fallback 降级为 H5。这样在不改变行数的前提下，既规范了层级又避免了在第二行重复添加上下文。

## 4. 字典键值剥离序号导致 Step 5 校验不匹配
- **问题**：
  - LLM 容易过度清理 `TOC_HEADINGS` 字典的键，剥离了前面的小节序号（如将 `1 生活中的立体图形` 简写为 `生活中的立体图形`）。
  - 这导致 Step 3 重写后的标题与 `toc.md`（保留了 `1`）不一致，触发了 Step 5 的校验失配。
- **措施**：
  - 优化 `step3_heading_processor_prompt.md` 字典构造规则，加粗强调**必须原样保留标题开头的章节号和序号前缀**，仅去除末尾的页码和导引符，保证两端数据的精确一致。

## 5. Stage 2 阶段图片改写导致图片丢失校验失败
- **问题**：在 Stage 2 内容处理阶段（`step6-content-processing`），LLM 生成的内容处理器（`content_processor.py`）尝试将标准的 Markdown 图片语法 `![](images/...)` 改写为 HTML 的 `<img>` 标签或用 `<center>` 包裹。然而，自检管道中的保存性校验（Preservation validation）只统计和追踪标准的 Markdown 图片语法，此类转换直接导致检测到的图片数量发生锐减（如从 516 降至 177），进而触发校验失败。
- **措施**：
  - 更新 `skills/mathos-formatting/agents/step6_content_processor_prompt.md` 提示词，明确禁止将 Markdown 图片语法改写为任何形式的 HTML 图片标签，强制要求必须原样保留 `![](...)` 格式。

## 6. 书籍正文包含而目录缺失的标题对齐问题
- **问题**：实体书籍可能存在正文实际存在某级标题，但书籍目录本身却遗漏了该项的情况。这会导致完全基于 TOC 自动生成的 `heading_processor.py` 与实际正文结构失配，从而在 Step 5 的校验中报错。
- **措施**：
  - 对于此类目录天生缺失标题的边缘情况，允许在工作目录中手动编辑和对齐 `heading_processor.py` 与 `heading_expected_result.md` 的层级结构，再通过不清除工作目录的方式直接 rerun 后续的格式化与校验管道，重用修改后的处理器以安全通过自检。

## 7. 拆分标题合并导致的后续重复匹配与层级偏移
- **问题**：在 H1 章节标题拆分（如 `## 第四章` 与 `## 因式分解`）的前瞻合并逻辑中，合并了第二部分标题后，未将该被合并行的行号或索引排除。当循环执行到被合并行时，由于其内容符合 TOC 尾部匹配规则（如 `因式分解` 后缀匹配 `1 因式分解`），该行会被再次独立格式化为 TOC 标题（如 `## 1 因式分解`）。这产生了两个 `1 因式分解` 标题，导致自检管道中的标题结构整体偏移 1 位，从而在后续的 Step 5 校验中大面积报错。
- **措施**：
  - 优化 `heading_processor.py`：在执行前瞻合并时，记录被合并标题的行索引到 `merged_indices` 集合中。
  - 在遍历处理的循环开头增加判定：如果当前行索引存在于 `merged_indices` 中，说明其已被前文合并，此时直接将其降级为非 TOC 的 H5/H6 标题并跳过后续匹配逻辑，避免重复格式化与索引偏移。

## 8. 书籍特殊栏目标题与预期层级不一致导致的自检失败
- **问题**：在自动化 run 管道中，生成 `heading_processor.py` 和生成 `heading_expected_result.md` 是由两次独立的 LLM 调用完成的。对于书籍中的特殊栏目（如 "回顾与思考"、"复习题"、"☆ 问题解决..."），由于没有明确 of 序号，两个独立调用可能会给出不一致的层级判断（例如处理器脚本将其映射为 level 2 `##`，而预期结构期望 level 3 `###`），导致 Step 5 对齐检验失败。
- **措施**：
  - 遵循 `SKILL.md` 中关于手动对齐的规范：对于此类没有序号的特殊栏目（回顾与思考、复习题、问题解决等），应确保将其在 `heading_processor.py` 的 `TOC_HEADINGS` 字典中统一配置为 level 3（H3），使其与期待的级别一致。
  - 在后续的 Prompt 调优中，可进一步约束模型对此类特定栏目层级的一致性判断。

## 9. 八年级上册第四章拆分标题 loose 匹配导致顺序错乱
- **问题**：在八年级上册中，第四章章节标题被分割为了两行：`## 第四章` 与 `## 一次函数`。若未做单行合并，第二行 `## 一次函数` 会由于 loose 模式（后缀匹配等）匹配到 TOC 的小节标题 `2 认识一次函数`（因均包含 `一次函数` 后缀），导致该章节标题被错误重写为 `## 2 认识一次函数`，引发正文标题顺序与结构大面积错乱。
- **措施**：
  - 手动将该 split 标题合并为单行 `## 第四章 一次函数` 即可彻底规避该问题。
  - 在生成 `heading_processor.py` 的 prompt 中，集成了 `merged_indices` 自动记录并降级前瞻合并行索引的逻辑，使拆分标题的第二部分能够在代码执行时被自动安全降级（降为 H5/H6 并且不参与 TOC 匹配），从技术底层防止再次出现此类 loose 匹配干扰。

## 10. 实体书籍目录缺失章节标题与《九章算术》引入部分的处理
- **问题**：八年级上册正文中存在第五章第五节的实际标题，但原书目录（TOC）中却彻底缺失了该项，且正文中《九章算术》引入部分上方缺少了应有的节标题。
- **措施**：
  - 在进行格式化之前，手动在正文中《九章算术》引入部分上方插入书中缺失的第五章第五节标题（或在 `heading_processor.py` 与 `heading_expected_result.md` 中手动补全对齐），以维护书籍整体的节结构完整性。
