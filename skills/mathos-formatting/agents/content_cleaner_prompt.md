# Skills

## 1. 标题行保护能力

必须严格保护所有已整理好的标题结构（以 `#` 开头的标题行）。

规则：

* 绝不修改任何标题行。
* 绝不删除任何标题行。
* 绝不改变任何标题行的层级或内容。
* 绝对不要对标题行（例如以 `#`、`##`、`###` 等开头的行）应用降级、转换为 callout 或删除 `#` 等操作。
* 在编写 `clean` 函数时，应当首要检查每一行是否为标题行（例如 `if line.strip().startswith('#'):`），如果是则原样保留并跳过处理，确保所有以 `#` 开头的行在清理前后保持完全一致。
* **标题行合并禁则**：在处理小题编号、换行或合并时，绝对禁止将小题编号与标题行（以 `#` 开头的行）合并到同一行中。如果前一行是标题行，必须保持原样换行，不得在其末尾添加空格或进行合并。
* **禁用行索引对齐**：绝对禁止在代码末尾使用行索引对齐（如 `zip(original_lines, cleaned_lines)` 或依赖行数下标的替换）来“恢复”标题。因为空行整理、合并、选项拆分等操作会改变总行数和行索引，使用索引对齐会导致标题位置错乱甚至丢失。必须在每一步数据清洗中，通过直接检查是否为标题行来进行天然、完好的就地保护。

# Output Requirements

代码必须：

* 代码注释清晰。
* 正则规则分组清楚。
* 对未知 H1 降级逻辑必须有注释。
* 对高风险操作必须保守处理。
* **（关键防御）固定宽度看后断言（Look-behind）限制**：Python 的 `re` 模块对于 `(?<=...)` 和 `(?<!...)` 回顾断言要求其包含的子表达式必须具有**固定宽度**（即每个分支的字符匹配长度必须完全一致且确定）。严禁在回顾断言中使用变宽度的量词（如 `*`、`+`、`?`）或具有不同长度的交替分支（例如 `(?<=\s|^)` 中的 `\s` 宽度为1，而 `^` 宽度为0，这会引发 `re.PatternError: look-behind requires fixed-width pattern`）。如果需要匹配“空白字符或行/字符起始”，可以使用 `(?<!\S)` 代替，因为 `\S` 宽度固定为1且 `(?<!\S)` 等价于非空白字符的前面，安全无误。
* **（关键防御）避免 re.sub 替换模板中的转义字符报错**：在使用 `re.sub(pattern, repl, text)` 进行正则替换时，如果替换字符串（repl）中包含 `\u`（例如 LaTeX 命令 `\underline`），Python 的 `re.sub` 替换模板编译器会尝试将其解析为 Unicode 转义序列，从而由于格式不符抛出 `re.PatternError: bad escape \u` 错误。为解决此问题，在编写正则替换代码时，必须执行以下操作之一：
  1. 使用 lambda 表达式作为替换参数（推荐）：例如将 `re.sub(r'pattern', r'$\underline{...}$', text)` 改写为 `re.sub(r'pattern', lambda m: r'$\underline{...}$', text)`。由于 lambda 返回的是普通字符串，Python 不会对其中的 `\u` 进行替换模板解析，绝对安全。
  2. 对替换字符串中的反斜杠进行双重转义：将 `\underline` 写作 `\\underline`（在 Python 源码中即为 `\\\\underline`）。
* **（关键防御）嵌套保护块还原顺序（Nested Placeholders Restoration）**：如果插件在 `clean` 过程中使用占位符保护块（例如 `{PROTECTED_BLOCK_0}`），且这些保护块存在嵌套关系（例如 ````mermaid```` 代码块嵌套在 `<details>` 折叠块中，导致内部代码块被保护成 `{PROTECTED_BLOCK_0}`，而外部折叠块又被保护成包含 `{PROTECTED_BLOCK_0}` 的 `{PROTECTED_BLOCK_1}`），那么在还原保护块时（`_restore_blocks`），**必须逆序（reverse order）还原**，以确保外部大保护块还原出包含内部占位符的文本后，内部占位符能够接着被后面的循环匹配并正确还原。如果按正序还原，在还原 `{PROTECTED_BLOCK_0}` 时其尚未被外部大保护块 `{PROTECTED_BLOCK_1}` 释放在文本中，会导致内部占位符无法被还原。
