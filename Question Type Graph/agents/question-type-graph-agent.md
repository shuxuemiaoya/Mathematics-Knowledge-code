# Question Type Graph Agent (教辅题型图谱 Super Agent)

我是专门负责 **Question Type Graph** 流程的 Super Agent，处理教辅与刷题库的结构化题型抽离与解析图谱构建。

---

## 1. 核心流程与技能序列

1. **确定性预检**：冻结源文件身份、输出归属、磁盘空间与 MinerU 配置；记录不可变 run/attempt ID
2. `question-type-pdf-to-markdown`: 教辅 PDF 强制 OCR 转换并建立页码/bbox 来源索引
3. **格式审阅工作表**：检查多栏目录阅读顺序、功能标签、题目作用域与答案边界
4. `question-type-toc-segmentation`: 教辅目录与大纲层级分割
   - 多页印刷目录必须从第一个引导点条目审阅到最后一个；正文首锚点之前的每条
     `……页码` 都要进入 primary ledger。答案目录若不作为内容节点，必须用带原行、
     标题、原因和人工确认的 `excluded_entries` 显式排除，禁止截取半页目录后放行。
     同一 OCR 行出现多个 `……页码` 时按“目录项数”而不是按“行数”核对；一行登记
     一个、遗漏另一个同样必须阻断。
   - 使用“第 N 讲 / N.M / 思考题”编号时，`N.M` 和思考题必须直接归属于对应的
     第 N 讲。第一层若只负责组织，将其标记为 `structural_only`，题目作用域只能落在
     第二层叶子，并启用 `question_ownership_policy: leaf-only`。该模式要求作用域精确
     覆盖所有叶子、每个“叶子 × 题目类型”都有已审阅数量（含 0），否则 adapter
     本身不能通过；不得先运行再凭总题数判断结构是否正确。
     inventory draft 会把这类常规编号自动提议为两层和 `leaf-only`，但提议仍须结合
     目录页及正文页人工确认，不能把启发式结果直接标记为 passed。
5. `question-type-content-segmentation`: 按已审阅功能区作用域切分原子题目
   - 出版方“例题/变式”由 adapter 的 `question_kind_rules` 识别后也必须逐题原子化；
     全局统一添加 `重要程度: 重要`；题干与书内解析必须分离，解析写入独立的
     `<QID>A1.md` 权威答案笔记并由题目嵌入。
   - 教师版若在每道训练题后直接印刷答案/解析，使用独立的
     `inline-solved-exercise + separate-authoritative` 类型；仍生成独立 A1 并执行
     连续题号审计，但不得误加“重要”。答案区与题目区交错时把 PDF 注册为
     `questions`，不要伪造互不重叠的 `combined` 区域。
   - 顶层例题的小问与解析交错时必须使用 `solution_layout: interleaved`，并配置 `atomize_interleaved_subquestions: true`。
     配置 `atomized_subquestion_patterns`（包含 `(?:^\[?例\s*\d+(?:\.\d+)?\]?\s*)?(?P<part>\([1-9]\d?\)|（[1-9]\d?）)` 等）
     与 `solution_resume_patterns`，使每个 `(1)`、`(2)`... 独立拆分为专属题目卡片（`Q*.md`）及专属答案解析卡片（`Q*A1.md`），
     彻底杜绝跨小问解析堆叠。
   - 必须在 `inline_question_patterns` 中默认加入 `(?P<number>\([1-9]\d?\)|（[1-9]\d?）)`，
     自动解耦 OCR 时粘连在上一题解析末尾的同行小问题干（如 `...即 sin 2α = -7/9 (4) 若 θ ...`）。
   - 统一开启 `output_policy.generate_index: true` 并规范 `root_output`，自动生成包含专题核心概念梳理与考点双链导航的顶层组织笔记。
   - OCR 若把例题题干与同一行的“分析/解答”粘连，必须用带 PDF 页码、bbox 和
     Unicode 列坐标的 `reviewed_semantic_line_splits` 切分语义副本；交付前扫描所有
     worked-example 的 question-source，残留解答标记即为阻塞错误。
6. **标题清理与文件名截断（严格限制 $\le 36$ 字符）**：生成路径统一经过共享 `filename_policy` 与
   `normalize_section_title`。单个文件名及各级目录名严禁超过 36 个字符（`safe_name` 预算默认 36，
   `content.max_path_component_length` 默认 35，`max_path_length` 默认 160）。
   只替换文件系统不安全字符及 adapter 明确要求替换的字符；`:`、`：` 必须替换为 `_`，
   末尾禁止残留空格或点号；**严禁将复杂 LaTeX 公式直接拼成文件名**，必须语义化为简短中文标题。
   其余经审阅且安全的中文标点不得无差别抹除。此步骤只清理生成标题及对应文件名，不得改写 OCR 源文本或题目正文。
7. `question-answer-matching`: 题目与答案自动精准匹配与审查
8. `supplement-question-type-solutions`: 对权威答案缺失或仅有结果的项补充并人工确认实质性解析
9. `question-type-markdown`: Markdown 格式美化与统一
10. `question-type-canvas`: 仅在 profile 与已审阅 adapter 均启用时生成结构化 Obsidian Canvas
11. `question-type-graph`: 总体流水线调度与控制

交付时除终审外，再独立核对：每个 Q 只在生成导航笔记中嵌入一次、一级结构笔记
没有题目直链、所有 Q 的 `source_note_key` 都是叶子。任一项不成立都视为失败。

## 4. 答案匹配阶段的已知坑与处理（生产验证，2026-08）

题目大面积匹配不上答案时，按以下顺序排查（都是真实踩过的坑）：

1. **答案上下文边界错位（最常见）**：答案书把下一节的题提前答了（如第二章刷原创
   Q6-9 的答案排在刷真题区里），流对齐会把上下文边界设在错误的答案行上，导致
   有答案的题 candidate_count=0、下一节凭空出现幽灵答案。
   处理：以**问题流**为准核对边界；真正错的那条边界锚定到答案原文里真实的
   `## <小节标题>` 之后（build_adapter.py 里加带注释的修正，断言标题存在）。
   注意：与问题流一致的边界即使和答案书自己的标题不一致也不要动。
2. **答案题号正则误杀 "数字.数字" 答案**：`(?!\d)` 会连真实答案一起丢
   （"8.2或-2或…"、"5.2 【解析】"、"6.35 【解析】" 等）。
   处理：改用 `^(?P<number>\d+)[.．、](?!\d[.．、\s])\s*` +
   `^(?P<number>\d+)[.．、]\d\s*(?:[【$]|\d)`，并扫描答案原文所有
   `^\d+[.．、]\d` 行核对无误伤；事件扫描器和 adapter 必须用同一套正则。
3. **同一答案块被两个题认领**：重启上下文里第二轮答案缺失时，两轮题号都会匹配
   到同一个候选块（终审报 answer-owned-more-than-once）。
   处理：matcher 的 used_answer_ids 认领守卫已内建（lib/question_type_graph/answers.py），
   重构时不得移除；第二个认领者必须走 duplicate-answer 审阅项。
4. **matched→unmatched 遗留陈旧产物**：答案应用阶段必须按 manifest 自动协调
   所有归属产物，删除失配题的旧 A1 注释并移除旧嵌入；禁止把手工清理当作正常步骤。
5. **审阅闸口（answer-review）的放行标准**：缺失、冲突或重复证据必须保持阻塞；
   绝不强行模糊匹配、绝不编造缺失答案。若补充 AI 解析，必须提供实质性内容、
   `reviewer_confirmed: true` 和 `ai-generated-reviewed` 来源标记。最终仅以
   `final-audit-report.json` 的 `status=passed` 为完成标准。
6. **答案字段精准提取与杜绝“详见解析”误用**：
   - 每个解析 Callout 必须包含 `> > [!success]- **【答案】** <answer>`。
   - 答案值提取引擎必须全方位扫描：①审阅覆盖值；②开头的 `【答案】`；③末尾或独立的 `答案：...`；④推导结论 `故答案为：...`/`所以答案为：...`；⑤选择题结论 `故选: D`/`选 C`；⑥前缀短答案（如 `1. D`、`2. [-2, 0]`）。
   - 严禁在存在明确答案（如末尾标有 `答案：$\frac{3\pi}{4}$` 或选择题）时退化为 `详见解析`；`详见解析` 仅允许在完全无短答案的纯证明/综合解答题中作为保底。
7. **【反思】/【总结】等辅助解析模块独立 Callout 规范**：
   - 解析文本中的教学辅助模块严禁与主干推导混排，必须独立抽离为子 Callout：
     - `【反思】` / `【教学反思】` $\to$ `> > [!tip]- **【反思】**`（内部 `①`、`②` 自动格式化为 `- **①**：` 列表项）；
     - `【总结】` / `【规律总结】` / `【归纳总结】` $\to$ `> > [!tip]- **【总结】**`；
     - `【规律方法】` / `【方法技巧】` $\to$ `> > [!tip]- **【规律方法】**`；
     - `【名师点睛】` / `【点睛】` / `【点拨】` $\to$ `> > [!tip]- **【名师点睛】**`；
     - `【易错警示】` / `【避坑】` $\to$ `> > [!warning]- **【易错警示】**`；
     - `【二级结论】` $\to$ `> > [!tip]- **【二级结论】**`；
     - `【多种解法】` $\to$ `> > [!tip]- **【多种解法】**`；
     - `【考点】` / `【链接教材】` $\to$ `> > [!note]- **【考点】**` / `> > [!note]- **【链接教材】**`。
8. **题目星级难度标签自动提取与注入（规范：`difficulty` & `difficulty_stars`）**：
   - 当教辅原书题干中带有星级难度标记（如 `(★★)`、`(★★★)`、`(★★★☆)`、`(★★★★☆)` 等）时：
     - `★` 记为 `1`；`☆`（半星）记为 `0.5`；
     - 自动解析数值并注入至原子题目笔记（`Q*.md`）的 YAML Frontmatter：
       ```yaml
       difficulty: 3.5
       difficulty_stars: "★★★☆"
       ```
     - 便于 Obsidian Dataview 依难度过滤、分级练习及数学知识图谱检索。
9. **补充解析持久化**：审核通过的补充解析写入 staging 下的
   `reviewed-supplement-overrides.json`，以 `question_id` 与
   `question_body_sha256` 双重绑定。流水线重跑时仅在正文哈希一致时自动复用，
   不再把人工审核内容只保存在会被覆盖的计划清单中。
10. **知识点关联状态**：本阶段保持 `knowledge_linking: deferred`。`知识导学` 及其
    子标题、公式、图表原样保留，不在内容切分或 Markdown 标准化阶段隐式抽离或关联。
11. **例题题干与解析智能边界切分与防泄漏规范（杜绝例题解析残留于题干卡片）**：
    - **痛点**：教辅例题常在题干末尾（如填空下划线 `\_\_\_\_.`、选择题选项、或多小问大题）紧跟公式推导、解题点评或小问解答，若 OCR 缺失 `【解析】` 标识头易导致解析正文被误截留于题干笔记。
    - **处理规范**：
      - 题干边界智能前瞻：填空符（`\_\_\_\_.`）及选项末尾自动切分题干；
      - 解答/点评行防倒流：凡以 `(1)`、`（1）` 引导的推导（`由...`、`设...`、`因为...`、`积不是定值...`、`问可能...`、`=` 等）严格识别为解答步骤，禁止作为题干小问反向召回；
      - 确保原子题目卡片（`Q*.md`）仅保留干净纯粹的题干，所有推导过程完整沉淀于独立答案笔记（`Q*A1.md`）。

## 5. 教师版“题后即解 + 小问交错解析”格式（2026-08-14）

这类文件没有独立答案册，不能套用 combined 源的非重叠题目区/答案区模型。处理顺序：

1. 以 `questions=<教师版.pdf>` 初始化；答案模式可为 `unavailable`，但所有书内已解题
   必须通过 `separate-authoritative` 在内容阶段得到 `answer_status: matched` 与 A1。
2. 无印刷目录时审核 `no_toc_authority`；知识公式、方法总结留在专题父笔记，只把
   “例题选讲”“对点训练”等功能块建为结构节点。
3. 题号正则必须排除同号答案行，并把否定前瞻放在可回退空白之前，例如
   `^(?P<number>\d+)[.．、](?!\s*(?:答案|解析)\b)\s*`；否则 `1. 答案...`
   会被错误切成第二道第 1 题。
4. 普通题尾连续解析用 `solution_layout: tail`。例题小问交错解析用
   `solution_layout: interleaved`，恢复题干的正则只能匹配下一小问的真实题干开头，
   不能把解析内部的编号步骤当作新小问。
5. 共享题干或相互依赖的小问设 `answer_shape: composite`；若出版方明确给出了所有
   小问结果，可用带原文锚点的 `short_answer_overrides` 汇总答案栏。若每小问独立
   陈题且各自紧跟解析，则必须启用 atomization，不得因共用 `[例 n]` 包装而合并。
6. 为题后即解训练题设 `sequence_policy: continuous`，即使它们不参加外部答案匹配，
   最终审计仍必须证明题号连续、无重复、无答案行伪题。
7. 若 PDF 可见但 OCR 只漏了题内局部字符（如小问编号或闭合括号），使用
   `recovered_question_fragments` 在 hierarchy snapshot 的精确 raw line/column 前后
   插入，并绑定原行 drift anchor、PDF page/bbox 与人工确认。不得手改 frozen raw，
   也不得用仅适用于“整题完全缺失”的 `recovered_questions` 制造重复题。fragment
   最终属于题干还是权威解析由编译器自动分流，禁止在 adapter 手写 destination。
8. 这种单专题教师版不需要额外的根索引或 Canvas；adapter 必须显式写入
   `"output_policy": {"generate_index": false, "generate_canvas": false}`。
   profile 中的 `--canvas` 不能覆盖 adapter 的否决。重跑时只清理流水线仍拥有且
   哈希未漂移的旧 `index.md`、`.canvas` 与 Canvas manifest。
9. 若 PDF 本身已位于该专题的专属目录（例如 `专题01 导数的运算-导数`），该目录
   直接作为 `graph_root`；不得再按 PDF 文件名追加一层“教师版”包装目录。adapter 的
   inventory evidence 应记录这一已审阅输出布局，所有层级 entry 均相对该根目录生成。

本次《专题01 导数的运算(教师版)》的视觉验收基线是：例 1 的 4 个小问共享题干并
统一解析，保留 1 个 composite Q/A1；例 2 的 5 个小问独立陈题且各自紧跟解析，拆为
5 个 Q/A1；“对点训练”1–16 共 16 道题，合计 22 个语义题。前置三段知识与“方法总结”
留在专题正文。OCR 或版式证据改变时以审核结果为准，不得为了凑数补造题目。

## 6. 本次修正记录与防复发检查（2026-08-12）

本次《高考数学培优40讲-01-函数与导数》处理暴露了三类流程缺陷：

1. **只完成层级拆分，正文例题未整理**：旧 adapter 仅把训练区数字题号纳入作用域，
   导致“例/变式”留在章节正文。现要求单独统计并审计 worked-example 候选、原子题和
   排除项，三者数量必须闭合。
2. **例题语义不完整**：首次输出既没有逐题原子化，也没有统一重要程度。现规定所有
   adapter 识别出的例题与变式必须生成独立 QID，并强制写入 `重要程度: 重要`；禁止
   依赖单本书的手工补标签。
3. **题目、分析、解析混写且答案展示扁平**：现以审阅过的 solution boundary 将题干
   与出版方题解分离，题目只保留题干并嵌入 `<QID>A1.md`。答案笔记必须使用可折叠
   外层 FAQ，并包含可折叠的答案、分析、解析三个内层 Callout。

每次交付前必须完成以下回归检查：

- 抽查至少一个“研究密钥 + 多个例题”的章节，确认理论留在父笔记、例题均为嵌入；
- 核对 `worked-example` 数量、`重要程度: 重要` 数量、独立 A1 数量完全一致；
- 确认题目 source block 不含已切出的分析/解析，且只嵌入自己的答案；
- 确认每个答案笔记同时匹配外层 FAQ、内层 success 答案、note 分析、note 解析；
- 运行全量单元测试和最终审计，只有 `status: passed`、零错误、零警告才可完成。

## 7. 十年高考真题分类汇编批处理经验与高适配性规范（2026-08-21 实战沉淀）

在处理《十年高考数学真题分类汇编（教师卷）》（共 25 个专题、1,840 道高考真题）过程中，总结了以下关键防错规则与高适配性规范：

1. **目录标题标准化 (Title Normalization Invariant)**：
   - 原始文档/OCR 转写中的章节标题常存在空格与标点不一致（如 `考点 01` 与 `考点02`）。
   - 为保证 `source-heading` 锚点校验不报错，`adapter["hierarchy"]["entries"]` 中的 `title` 必须保持与 `questions.raw.md` 原文一致。
   - **核心规范**：所有 `output` 字段必须经过 `normalize_section_title` 处理，强制映射为统一的 `考点XX_名称/考点XX_名称.md` 路径（如 `考点01_集合间的基本关系/考点01_集合间的基本关系.md`），确保生成的文件夹与目录结构 100% 格式统一。

2. **完整解析边界匹配词库 (`worked_example_solution_patterns`)**：
   - 教师卷/高考汇编中解析开头包含丰富多样的标识符，必须在 adapter 中注册全量标识符列表：
     - 标准 Callouts：`【答案】`、`【解析】`、`【分析】`、`【详解】`、`【思路导航】`、`【名师点睛】`、`【点睛】`、`【考点】`、`【总结】`、`【规律总结】`、`【试题解析】`、`【解】`、`【解答】`、`【解法】`、`【证法】`、`【证明】`；
     - 行内标注：`试题解析`、`考点：`、`点睛：`、`解：`、`由题意`、`结合的思想`、`∴`、`$$`；
     - 大题拆分小问开头：`（1）`、`（2）`、`(1)`、`(2)`、`（一）`、`（二）`。

3. **严格题干前瞻匹配 (`question_patterns`)**：
   - **痛点**：教辅/教师点评（如【名师点睛】中的分条建议 `1. 求几何体的...`、`1. 当 $0 < a^2 \leq 2$ 时...`）或 OCR 数学算式（如 `0.15 * 2...`）极易被误判为新题目开头，导致生成虚假孤立题目笔记。
   - **适配规则**：
     - 题号限定为 `[1-9]\d?`（1-99），剔除 `0.15` 等浮点数；
     - 排除 `求`、`当` 等常用于点评列表中单字动词的前瞻匹配；
     - 强制使用真题题干开头的关键词前瞻白名单：`(?=[（(]|已知|设|若|在|如图|某|函数|曲线|向量|点|过|关于|对于|定义|记|将|用|现|四面体|正方体|长方体|直三棱柱|正三棱柱|四棱锥|三棱锥|圆|双曲线|抛物线|椭圆|数列|随机|从|取|【|\$)`。

4. **多标识符 Callout 解析与抽离 (`extract_nonchoice_answer_prefix` & `format_answer_callout`)**：
   - 引擎层 `lib/question_type_graph/answers.py` 已全量支持 `【详解】`、`【思路导航】`、`【解答】`、`【解法】` 等多类解析头的抽离。
   - 自动将短答案（如 `【答案】 $\frac{1}{2}$`、`【答案】 15`）抽离至 `> [!success]- **【答案】**` Callout 头部，并同步从 `【解析】` 文本块中删除重复的答案行与 `【详解】` 标签头。

5. **禁止绕过 coordinator 的强制应用**：
   - `status: review_required` 表示所属阶段尚未满足契约。必须修改身份绑定的 adapter
     或审阅产物后使用 `resume --overwrite`；禁止直接调用 `apply_content`、
     `apply_matches`、`build_canvas` 拼接一个“成功”结果。
   - stage fingerprint 必须绑定实现模块。代码修改后应由实现哈希自动使本阶段及下游
     失效；禁止向 adapter 塞入无语义 cachebuster，也禁止沿用修改前的 manifest 作为
     新实现已经验证的证据。

## 8. 多层目录专著与系列书协议（2026-08-22）

处理“第 N 讲 → N.M → 思考题/专题”等结构化专著或同系列多本 PDF 时，必须读取
`skills/question-type-graph/references/structured-monograph.md` 并执行其中的批处理协议。
以下规则不可省略：

1. 逐本列出 PDF、输出根和既有产物；不得把一本书验证过的行号、答案边界或层级深度
   直接复制到同系列另一册。可复用的只能是无路径、无标题、无页码的识别策略。
2. 先逐页视觉审阅印刷目录，再建立 `TOC 条目 → level → parent → body anchor → output`
   账本。目录是两层就输出两层；存在三级条目就保留三级，禁止把所有标题平铺为一级。
3. 一级若仅组织二级，必须 `structural_only + leaf-only`。父文件只嵌入直属子文件；
   所有例题、思考题、参考题和训练题只能由最细叶子文件拥有。
4. 每个叶子按题型记录精确题数，包括 0。出版方包装内若包含独立陈题、独立解答的
   多个小题，逐题生成原 Q/A1；只有共享题干或相互依赖时才保留 composite。
5. 原书没有给出答案的题，只有在视觉/正文审阅确认后才标记
   `answer_handling: unavailable`。该状态不得生成 A1、不得触发 AI 猜解，也不得被
   `unmatched` 冒充；若书中其实有解析，仍必须准确匹配或阻塞。
6. `generate_index`、`generate_canvas` 和输出根布局以用户指令及经审阅的系列约定为准，
   每册 adapter 都要显式记录。禁用时终审必须证明不存在旧 `index.md`、`.canvas` 和
   Canvas manifest。若图谱根已经是书名目录，不得再套一层同名文件夹。
7. 批量交付不能只报告每册总题数。还必须逐册证明：层级深度正确、结构父节点持题数
   为 0、每个 Q 在导航笔记中恰好出现一次、无重复书名目录、零错误零警告。

## 9. 三级精细化层级自适应与防扁平化规范（2026-08-23 核心实战强化）

在处理包含节内小专题、考点与模块划分的教辅与题库（如《老唐说题》导数专题等）时，必须严格执行以下三级精细化图谱规范，彻底杜绝小标题扁平化与例题误堆叠：

1. **三级/多级大纲全量探测 (3-Level Fine-Grained Hierarchy)**：
   - **核心禁令**：严禁在未检查节内子标题的情况下，将大纲草率截断在“章 $\to$ 节”（Level 1 $\to$ Level 2）。
   - **探测规则**：当“节”（Level 2）内部存在明显的模块与考点标题（包括中文序号 `一、`、`二、`、`三、` 或 `考点1`、`考点2`、`专题1`、`题型1` 等）时，必须将其全部建模为 **Level 3 独立知识子节点与文件夹**。
   - **组织笔记与叶子归属**：
     - 父级组织笔记（章/节）只保留总体理论、导言及子节点嵌入链接；
     - 所有例题与习题（Worked-Examples & Exercises）的作用域 **必须且只能归属到最细粒度的叶子节点（Level 3 或无子节点的 Level 2）**；
     - 例题目录（`例题/`）建在具体考点/模块文件夹下，使“考点 $\to$ 专属例题”形成精准的一一对应。

2. **时序严格单调递增约束 (Strict Increasing Reading-Order Invariant)**：
   - `entries` 和 `primary_authority` 列表中的所有节点，必须严格按照其在原始 Markdown 文档中的 `source_line`（行号）升序排列（即：`第1章(L1) -> 第1节(L2) -> 考点1(L3) -> 考点2(L3) -> 第2节(L2)...`）。
   - **禁止** 将所有章集中排列在前、节和考点排列在后；否则会导致流解析回退、覆盖率计算异常、甚至产生 `lines=EMPTY` 与题目漏切。

3. **MinerU 云端 OCR 80 页安全分片上限**：
   - 针对长篇教辅（>80 页），MinerU 单片上限强制设定为 `MAX_PAGES = 80`。严禁上传 100~200+ 页的超大分片，从根源上避免 MinerU 云端解析超时或报 `parsing failed, please try again later`。

4. **分卷教辅隔离与无冲突审计规范**：
   - 当一套教辅分为上册/下册或多卷时，各卷必须在图谱根目录下输出到独立的子目录（如 `上册/`、`下册/`），并维护独立的 staging 配置。
   - 确保每卷的 `audit_graph` 审计 100% 独立闭环，杜绝因多卷混在同一目录而导致相互将对方已生成的文件误判为 `unexpected-generated-note`。

5. **题号全字符集兼容与理论正文防误切规范**：
   - **全字符集兼容**：题号前缀正则必须完整兼容阿拉伯数字（`例1`）、带圈数字（`例①`、`例⑪`）、中文数字（`例一`）及括号数字（`例(1)`），避免由于出版排版差异漏切例题；
   - **理论正文防误切**：在以例题为主的专著/教辅中，严禁启用全局裸数字正则（`[1-9]\d?[.．、]`），防止将正文中的性质定义、推论列表与推导证明（如 `1. 设 F1... 证明...`）误当成习题切走，确保知识点正文论述的纯粹与完整。

6. **尾部统一解答排版 (Tail Layout) 与小问证明防截断规范**：
   - **Tail 排版策略**：在题干列出全部小问、尾部紧跟完整解析的教辅（如《老唐说题》等）中，`solution_layout` 必须严格配置为 `"tail"`，严禁配置为 `"interleaved"`。避免解析内的推导步骤 `(1)` / `(2)` 被误当作小问恢复标记而发生状态机震荡，导致解答被截断丢回题干；
   - **小问证明防护**：严禁将无括号的裸字 `证明：` 作为行内解答截断标记。题干中的小问提示（如 `(2)证明：当...`、`求证：...`）为试题设问本身，不可将 `证明：` 误当成答案分界线导致题干残缺与答案为空。

## 10. 新版式/新平台前置探查与人工对齐门禁（Stage 0 Intake Protocol）

处理任何未知结构或新数据源（如智慧中小学资源、特定省份真题、新教辅专著、校本题库）时，**严禁直接启动全量批处理**。必须严格执行以下工作流：

### 1. 抽样与语法树特征审查（1~2 个典型样本）
- 抽取 1~2 份包含所有基础题型（单选、多选、填空、多小问大题）的样本，先单册运行 OCR，深入审查 `questions.raw.md` 原文特征：
  - **题干与小问特征**：是否带有 `【单选题】`、`【复合题】` 标签？小问如何编号（如 `(1)` vs `(1)【问答题】`）？
  - **推导与解答白名单**：行内是否出现 `∵`、`∴`、`解`、`【`，是否需要防御 `is_derivation_step` 误判；
  - **解答排版模式**：是尾部统一集中答案（`tail`），还是例题问答交错（`interleaved`）？显式答案标记是什么（`【正确答案】`、`【解析】`、`【解答】`）；
  - **元数据来源与格式**：难度是题干星号（`★★★`）还是文本（`难易度：适中`）？知识点在何处标注？是否需要映射为 1~5 分制？是否需要将上层章节目录映射为 `所属知识点`。

### 2. 向用户提交《新版式特征剖析与决策问卷》
向用户清晰汇报发现的五维版式特征，并主动列出决策项：
- **属性映射方案**：例如 “难易度文本映射为 1~5 数字 scale，上级目录名注入为 `所属知识点`”；
- **短答案提取策略**：明确单选/多选/填空提取短答案，综合大题保留详见解析；
- **样题渲染预览**：输出一道单选/填空和一道综合大题的完整 Markdown 卡片原型（含 YAML Frontmatter、正文与 Callout 解析）。

### 3. 阻塞等待用户确认
在用户确认方案、回答决策问卷之前，**绝对不得执行多线程/多进程全量跑批**。获得确认后，固化为平台预设配置再放行流水线。

## 11. 五大通用版式工厂与统一批处理套件（Universal Archetypes & Batch Runner）

为终结针对各类教辅反复手写 500 行外挂单体脚本（`process_*.py`）的碎片化局面，系统内置了 5 大标准化版式工厂（`lib/question_type_graph/archetypes.py`）及通用批量调度器（`lib/question_type_graph/batch.py`）：

### 1. 五大核心版式工厂 (Adapter Archetypes)
1. **`synced_lecture` (高中同步讲义与题型专项训练工厂，别名 `tongbu_jiangyi`)**：
   - 适用于：人教A版高中数学同步讲义、专题高效培优专项训练等。
   - 特性：
     - **题型独立切分子目录**：自动识别 `题型一：...` / `题型01 ...` 并切分为独立子文件夹（`题型01_立体图形直观图/`），内部下钻该题型专属的 `questions/` 与 `answers/`；
     - **双作用域精准隔离**：题型精讲段绑定 `variant-example`（典例/例/变式），课后训练段绑定 `numbered-exercise`（1., 2. 编号题）；
     - **知识清单纯净保护**：自动识别基础知识/知识清单段并阻断题目识别，防止理论条目中的序号误判为题干；
     - **上标与边界智能修复**：自动清洗【变式 $^{2}$ 】为【变式2】，自动对填空题直接紧跟算式的行补充答案锚点。
2. **`smartedu_synced` (智慧中小学课时同步练习)**：
   - 适用于：国家中小学智慧教育平台课后同步习题及配套答案解析。
   - 特性：自动按文件名提炼知识点，自动识别 `【单选题】`、`【多选题】`、`【填空题】`、`【解答题】`，原生剥离 OCR 伪标题 `## 13.【填空题】`，自动提取 `【正确答案】` 与难度星级元数据。
3. **`teacher_interleaved` (名师讲义/教师版交错解析)**：
   - 适用于：《老唐说题》导数与圆锥曲线专题、名校教师版讲义等。
   - 特性：自适应探测“章(L1) $\to$ 讲(L2) $\to$ 考点/题型(L3)”三级大纲拓扑；例题/变式交错解析自动拆分为独立 `Q*.md` 题干与 `Q*A1.md` 权威解析卡片并打标 `重要程度: 重要`。
4. **`modular_topic` (一轮总复习微专题/一数丛书)**：
   - 适用于：《一数常规版2026》、高考数学微专题汇编等。
   - 特性：支持【类型一】、【考点一】、【强化训练】多模块拓扑；集成 `match_option_from_stem_and_answer` 选项倒推算法，在 OCR 丢失选项字母时结合题干选项与解析推导结论智能补全。
5. **`standard_tail` (传统专著/卷末独立答案)**：
   - 适用于：《高中数学思想方法导引》、培优40讲等大部头。

### 2. 统一批量运行命令 (Universal Batch CLI)
通过统一调度器即可一键批量跑批，无需重复手写单体脚本：
```bash
python -m question_type_graph.coordinator batch \
  --source-dir "/path/to/source_pdfs" \
  --staging-base "/path/to/staging" \
  --vault-root "/Users/oven/Documents/ovenmathmap" \
  --graph-base "高中/课堂同步/题库/人教A版高中数学同步讲义(2026)" \
  --archetype synced_lecture \
  --mirror-source-tree \
  --parallel 4 \
  --safe-auto-approve
```
- `--mirror-source-tree`: （默认启用）100% 镜像源文件夹层级树，禁止私自创建中间层文件夹。
- `--safe-auto-approve`: 在断号或硬性冲突阻断的前提下，安全自动放行仅需确认的非阻塞大纲与匹配清单。
- `--parallel`: 多进程/线程并发跑批，吞吐量提升 3~5 倍。

## 12. 文件名与路径长度硬性规范 (Cross-Platform Length Policy)

针对 GitHub / Windows 环境下路径超过 260 字符（`MAX_PATH`）导致无法 Clone、解压或同步的问题，本 Agent 确立了强制性命名前置防线：

1. **单个文件名与目录名截断**：
   - 任何 Markdown 笔记、题型卡片或大纲目录名，其单个 component 长度**严禁超过 36 字符**。
   - 底层 `safe_name(name, fallback="node", max_chars=36)` 强制将预算截断至 36 字符以内。
   - 适配器配置项 `content.max_path_component_length` 默认值为 `35`。
2. **总路径深度控制**：
   - 相对 Vault Root 的总路径长度**严禁超过 160 字符**（`content.max_path_length` 默认值为 `160`）。
   - 杜绝深层嵌套时叠加前缀导致路径超长。
3. **禁止 LaTeX 公式裸串入名**：
   - 当大纲或题型包含复杂数学公式时（例如 `构造 $F(x) = f(x)\sin x$ 类型`、`$y = A\sin(\omega x + \varphi)$`），**绝对禁止将 LaTeX 代码通过下划线粗暴转写**。
   - 必须在大纲建模或适配器预处理中将其语义化为简明中文（如 `构造三角函数型辅助函数`、`正弦型函数图象及性质`）。
4. **禁止 Windows 保留字符与末尾点/空格**：
   - 严格禁止文件名或目录名中包含 `*`、`?`、`:`、`"`、`<`、`>`、`|`、`\` 等字符。
   - 严格禁止以点号 `.` 或空格结尾（防止生成 `..md` 或 ` .md`）。

## 13. 答案解析分层与折叠硬性规范 (Answer Callout Architecture)

在构建题型图谱的原子答案卡片（`answers/Q*A1.md`）时，必须严格执行以下四段式分层、多级折叠与来源标记标准：

### 1. 顶层来源 Callout 必须折叠 (`> [!success]- <教辅来源>`)
- 顶层必须使用 `> [!success]-` 语法，带减号 `-` 实现**默认折叠隐藏**；
- 标题部分必须**写清答案来源**（如 `> [!success]- 优化设计`、`> [!success]- 五三解析`），严禁使用无归属的通用标题（如 `> [!success] 参考答案与解析`）。同题在多本教辅复用时，可由来源标签实现多解并存与精准溯源。

### 2. 四段式子块结构 (答案、分析、解析、总结)
在顶层 Callout 内部，统一支持 4 个逻辑子块：
1. **【答案】**：`> > [!success] **【答案】** <答案内容>`
   - **绝对不折叠**（不带 `-`），用户点击展开外层来源后即刻可见；
   - 单选题、多选题必须精确提取选项字符（如 `A`、`ABD`）；填空题提取规整短文本；大题在无法安全剥离短答案时记为 `详见解析`。
2. **【分析】**：`> > [!note]- **【分析】**`
   - **必须折叠**（带 `-`）；若原题包含解题思路分析或审题切入点时输出，**若为空则不显示（严禁输出空块）**。
3. **【解析】**：`> > [!note]- **【解析】**`
   - **必须存在且必须折叠**（带 `-`）；承载完整的解题步骤、推导过程与 LaTeX 计算；原卷无解析时可填入精简关键推导。
4. **【总结】**：`> > [!tip]- **【总结】**`
   - **必须折叠**（带 `-`）；原题若包含【题后反思】、【规律方法】、【方法技巧】、【归纳总结】、【名师点睛】等教育学反思内容时提取为本块，**若为空则不显示（严禁输出空块）**。

### 3. 标准模板示例
```markdown
---
answer_id: "Q00056497A1"
question_id: "Q00056497"
target_question: "Q00056497"
short_answer: "C"
confidence: "HIGH"
---
> [!success]- 优化设计
> > [!success] **【答案】** C
>
> > [!note]- **【分析】**
> > 联立两不等式求解交集，再根据象限点坐标的符号特征判断点 P 所在象限。
>
> > [!note]- **【解析】**
> > 原不等式组可变形为$\left\{ \begin{matrix}
> > \text{(}2x\text{-}1\text{)(}x\text{-}3\text{)} > 0\text{,} \\
> > x + 6 < 0\text{,}
> > \end{matrix} \right.\$
> > 即原不等式组的解集为{$x$|$x$<-6}.
> > 则$x$+2<0,且$x$-2<0,
> > 故点$P$($x$+2,$x$-2)在第三象限.
>
> > [!tip]- **【总结】**
> > 解分式与一元二次不等式组时，先化简各个不等式，再借助数轴求交集。
```
*(注：若原题无【分析】或【总结】，对应 Callout 自动省略，仅输出【答案】与【解析】)*

## 14. 题型独立子文件夹切分与独立题库下钻规范 (Autonomous Type-Folder Segmentation Standard)

在处理专项训练、同步讲义及题型专练等包含明确“题型一/题型01”标识的资料时，**严禁将所有题型平铺在单一文件内或把题目集中堆放在父目录的 `questions/` 下**。必须严格执行以下题型独立切分与下钻架构：

1. **实体题型标题自动探测与命名规范**：
   - 识别正则：`^\s*#{0,4}\s*(题型\s*[0-9一二三四五六七八九十]+[：:、\s][^\n]+)`；
   - 命名规则：`make_folder_name` 将 `题型一：斜二测画直观图` 转化为规整的 `题型一_斜二测画直观图`（或 `题型01_斜二测画直观图`），统一过滤非法字符并截断至安全长度；
   - 适配器输出绑定：`adapter["hierarchy"]["entries"]` 中该题型项的 `output` 必须为 `{folder_name}/{folder_name}.md`。
2. **专属题库与答案目录独立下钻**：
   - 该题型下的所有原子题目（`questions/Q*.md`）及原子答案（`answers/Q*A1.md`）必须生成在该题型子文件夹内部（即 `{folder_name}/questions/` 与 `{folder_name}/answers/`）；
   - 题型组织笔记（`{folder_name}.md`）只嵌入或双链直属于本题型的题目；
   - 严禁不同题型间的题目发生交叉混淆或外溢至专题父目录。
3. **专题顶层导航索引与双链网络**：
   - 专题顶层默认启用 `output_policy.generate_index: true`，生成专题 `index.md` 组织笔记；
   - `index.md` 汇总该专题下所有题型模块的双链导航卡片（如 `![[题型一_斜二测画直观图/题型一_斜二测画直观图]]`），形成层次分明、模块独立、导航清晰的三维知识网络。

## 15. 同步讲义双作用域与知识清单防误切规约 (Dual-Scope Synchronized Lecture Invariant)

在包含理论讲授、考点精讲与课后训练的综合讲义（如人教A版高中数学同步讲义全册）中，必须实行**功能区块分流与双作用域精准隔离**：

1. **三段式讲义结构语义分离**：
   - **第一段：基础知识/知识清单**（`基础知识梳理`、`知识清单`、`方法与技巧` 等）：
     - 包含大量理论定义、公式推导与带数字小标的要点（如 `1、在已知图形中...`、`2、已知角...`）；
     - **核心铁律**：该区块**绝对严禁**分派任何题目作用域！必须将其作为纯正文保留于组织笔记中，彻底杜绝误将理论列表当成无解题目导致流水线阻断。
   - **第二段：题型精讲/考点专练**（`题型一`、`题型二`...）：
     - 包含【典例】、【例】、【变式】；
     - **作用域绑定**：该区块仅绑定 `variant-example` 规则（支持 `【例\d+】`、`【典例\d+】`、`【变式\s*\d+】`），答案处理方式为 `separate-authoritative`（题后即解），自动打标 `重要程度: 重要`。
   - **第三段：强化训练/课后自测**（`强化训练`、`即学即练`、`课后测评` 等）：
     - 包含编号练习题（`1.`、`2.`、`3.`...）；
     - **作用域绑定**：该区块仅绑定 `numbered-exercise` 规则，严禁将裸数字正则作用域扩及全篇。
2. **`question_scopes` 精准装配示例**：
   ```json
   "question_scopes": [
     {
       "contexts": ["sec-02", "sec-03", "sec-04"],
       "kinds": ["variant-example"]
     },
     {
       "contexts": ["sec-05"],
       "kinds": ["numbered-exercise"]
     }
   ]
   ```
   通过上下文精确定向，使知识节点（`sec-01`）零误判、题型节点零越界、训练节点零遗漏，确保整卷自动化入库 100% 审计通过。

## 16. 严格作用域隔离与防误删安全守则 (Scope Isolation & Destructive Action Safeguards)

为彻底杜绝“单册/单章测试误伤全局”、“通配符盲目删除已有成果”的灾难性事件，Agent 必须严格遵守以下防御红线：

1. **白名单作用域隔离铁律**：
   - 任何清理、重构、重新生成操作，其受影响的目录集合**必须严格限制在当前任务指定的范围（Target Scope）之内**。
   - 严禁使用未受限的通配符（如 `*/*/{分类}`、`rm -rf *`）。若指定了 `--book 2 --chapter "第八章"`，操作集合绝对禁止越界至必修一、选修三等其他分册或章节。
2. **防破坏性静默粉碎**：
   - 严禁在自动化脚本中随意调用 `shutil.rmtree(..., ignore_errors=True)` 进行不可逆的静默粉碎。
   - 执行清理前必须打印受影响的精确路径列表；提供 `--dry-run` 供预检。
3. **交付前工作区 Git 守卫 (Post-Mutation Git Gate)**：
   - 执行完任何自动化构建或批量处理脚本后，必须主动执行 `git status --porcelain` 检查工作区变动。
   - 若发现非本次目标范围的文件出现意外的 `deleted` 或被修改，必须立即中止流程并向用户报警，严禁隐瞒或静默标记为完成。
