# Pipeline Contract

| Stage | Required input | Output | Gate |
| --- | --- | --- | --- |
| Intake | typed sources and paths | `question-type-profile.json` | immutable source hashes and valid source arrangement |
| Preflight | frozen profile and invocation options | `preflight-report.json`, append-only run/attempt IDs | source identity, roots, credentials, output ownership, and working space pass without exposing secrets |
| PDF conversion | profile PDF role | raw Markdown, assets, report, `source-provenance-index.json` | forced OCR, complete ordered coverage, and hashed content-list page/bbox evidence |
| Format inventory | registered raw Markdown, provenance index, and optional frozen preset hints | `format-inventory.json`, `format-review-worksheet.md` | review all uncertain hierarchy, multi-entry TOC order proposals, parsed references, wrapped entries, labels, numbering, layout, and answer regions; no built-in publisher vocabulary |
| Hierarchy | passed adapter | hierarchy and coverage manifests, entry notes, and optional root index note | every primary-authority ledger entry is represented exactly once, every source line has one owner, local snapshot lines retain original Markdown-line mapping, and each direct child is embedded once with a standalone `![[...]]`; `output_policy.generate_index: false` suppresses the root note and rejects stale owned output |
| Content | hierarchy corpus and schema-valid adapter patterns | hierarchy-note properties, functional nodes, headingless atomic question notes, manifest | adapter-declared chapter metadata is moved to YAML frontmatter without duplication; explanatory introductions remain in their chapter notes unless explicitly reviewed as independent navigation nodes; a publisher example wrapper is not presumed to be one question: independently stated and independently solved `(1)(2)…` packet items become separate original Q/A1 pairs through reviewed adapter atomization, while genuinely shared-stem subparts remain one composite Q/A1; publisher worked-example leaves are marked `重要程度: 重要`, and their reviewed solution spans move to separate authoritative `<QID>A1.md` notes embedded from stem-only question leaves; other teacher-edition publisher-solved kinds may use the same authoritative separation without inheriting importance; reviewer-confirmed PDF-visible fragments omitted inside existing questions are inserted only in the semantic virtual copy through exact raw line/column and page/bbox provenance; question-bearing HTML tables are flattened into numbered semantic column streams; numeric detection respects reviewed question scopes and kinds; every external-answer context and every authoritative context with `sequence_policy: continuous` has a continuous `1..N` semantic question ledger, including reviewed source-anchored number-reset shifts where required; no output collisions, unresolved label review, list-prefixed embeds, orphan table-cell tags, or generated atomic-question headings; virtual-line and page/bbox provenance remain raw-addressable |
| Title cleanup | generated content titles and filenames | cleaned titles and corresponding filenames | every hierarchy path component uses the shared normalizer; `:` and `：` are always replaced by `_`, and final audit blocks either character in every generated file or directory path; immutable OCR text and question bodies remain unchanged |
| Answers | external-answer atomic questions, optional answer source, and schema-valid adapter patterns | answer-match manifest and standalone answer notes with collapsible nested `【答案】`, `【分析】`, and `【解析】` blocks | separate-authoritative worked-example answers bypass external matching but must pass the same standalone-note, embed, provenance, nested-Callout, and substantive-solution audits; every accepted external match is exact and uniquely owned; every authoritative answer owns a question (`unmatched-answer` is always blocking); PDF-visible raw omissions use reviewed page-provenanced `recovered_answers`; choice answers are exact; unresolved questions require explicit review before supplementation; fuzzy evidence never auto-passes |
| Solution supplement | reviewed unmatched questions | provenance-marked AI solution notes and application report | substantive solution text and `reviewer_confirmed: true`; placeholders never apply |
| Markdown | complete notes | standardization report | lexical signature unchanged |
| Canvas | passed manifests plus enabled profile and adapter policy | graph manifest and `.canvas`, or an explicit skipped stage | no atomic question cards or invalid endpoints; `output_policy.generate_canvas: false` overrides profile enablement and leaves no owned Canvas artifacts |
| Audit | complete corpus plus reviewed source question ledger | final report | source hashes, content hashes, links, answers, and all adapter-selected output-presence/absence checks pass; source ordinary-question plus independently solved packet-item counts equal Q and A1 ownership counts; no atomic Q contains multiple independently solved item starts; no generated hierarchy note repeats its semantic heading in the first two nonblank lines; representative first/middle/last source-versus-output checks pass |

The coordinator may stop with `review_required`. Resume only after updating the
identity-bound adapter or review artifact; do not bypass the owning stage. When
an authoritative answer is genuinely absent, explicitly approve that answer
review result, resume to generate `supplemental-solutions-manifest.json`, add and
review the worked solution, apply it, then resume the coordinator.
Persist reviewer-authored reusable solutions in
`reviewed-supplement-overrides.json`, keyed by question identity and body
digest, so safe pipeline replays do not erase reviewed work.

Every reusable stage fingerprint includes both immutable data inputs and the
concrete compiler modules used by that stage. A compiler implementation change
therefore invalidates stale artifacts and descendants automatically; never edit
adapter metadata merely to manufacture a cache miss.
