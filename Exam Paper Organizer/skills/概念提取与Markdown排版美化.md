## 全局规则

以下规则适用于所有任务：
1. 内容完整性优先。
2. 多图并排优先于单图居中处理。
3. 所有禁止修改的条目（如H1-H3标题、表格数据、链接路径、图片路径等）在任何操作下均不得修改。

## 任务 2：Markdown 排版整理

### 2.1 禁止修改内容

以下内容不得改写原意：
1. H1-H3标题。
2. 表格数据。
3. 链接路径。
4. 图片路径。

### 2.2 段落、空行、列表

#### 2.2.1 空行

1. 标题前后保留空行。
2. 公式块前后保留空行。
3. 图片块前后保留空行。
4. 表格前后保留空行。
5. 连续 3 行及以上空行压缩为 1 行。
6. 同一道题内部不要插入过多空行。
7. 题干、图片、选项、答案、解析之间保持相邻关系。

#### 2.2.2 列表

1. 同一级列表使用同一种编号格式。
2. 嵌套列表必须缩进。
3. 不要把连续列表拆成多个无关段落。

#### 2.2.3 选择题选项

选择题选项统一为以下两种格式之一。

格式一：

```markdown
A. 选项一  
B. 选项二  
C. 选项三  
D. 选项四
```

格式二：

```markdown
(A) 选项一  (B) 选项二  (C) 选项三  (D) 选项四
```

同一个文件内尽量使用同一种格式。

### 2.3 公式处理规则

#### 2.3.1 行内公式

1. 所有公式默认使用行内公式。

#### 2.3.2 行间公式

以下内容可以使用行间公式：
1. 重要结论。

#### 2.3.3 公式编号

1. 原文中的 ①②③④ 等公式编号必须保留。
2. 不改变原公式编号。
3. 不把公式编号改成脚注。

### 2.4 Callout 处理规则

#### 2.4.1 使用条件

以下内容可以转为 Callout：
1. 是标题的思考、探究等等（#开头的，一般为H4-H6）。
2. 例题。
普通题不转为 Callout。
练习题也不转为 Callout。

#### 2.4.2 Callout 类型
Callout 类型优先根据内容功能判断，不只按关键词机械匹配。栏目名称只是参考，最终以该部分在原文中的作用为准。

判断顺序：
1. 先判断内容功能：提问、探究、例题、分析、解答、提醒、总结、背景说明等。
3. 若栏目名和内容功能不一致，以内容功能为准。
4. 若功能不明确，保持普通 Markdown，不强行转为 Callout。
5. 普通正文、普通题目、普通练习题、连续讲解内容，不因出现个别关键词就转为 Callout。

| 内容功能                | 常见栏目 / 表现                                   | 建议 Callout        |
| :------------------ | :------------------------------------------ | :---------------- |
| 观察、思考、讨论、提出问题     | 思考、观察、交流、尝试、想一想、议一议、观察·思考、尝试·交流、思考·交流、回顾·反思 | `> [!question]`   |
| 探究规律、实验操作、发现结论      | 探究、实验、做一做、观察与猜想、操作与思考                       | `> [!question]`   |
| 引入、引导、情景引入  | 操作·交流      |  `> [!info] ` |
| 例题、典型问题、示范题         | 例、例题                             | `> [!example]-`   |
| 例题内部的分析、思路、点拨       | 分析、思路                                 | `> > [!tip]-`     |
| 例题内部的解答、证明、解析       | 解、证明、解析                                  | `> > [!success]-` |
| 易错提醒、限制条件、特别注意      | 注意、易错、说明                              | `> [!warning]`    |
| 背景、旁注、补充材料          | 背景、旁注                         | `> [!tip]`       |
| 类比、对照、辅助理解          | 联系、区别                                 | `> [!note]`       |
| 小结、归纳、方法、规律、核心结论    | 归纳、总结、法则、结论                        | `> [!summary]`    |
| 未单独提取的定理、公理、性质、核心知识 | 定理、公理、性质                            | `> [!summary]`    |

例题整体使用一级 `> [!example]-`。例题内部的“分析 / 思路 / 点拨”使用二级 `> > [!tip]-`，“解 / 证明 / 解析 / 解答”使用二级 `> > [!success]-`。

`> >` 只能用于已有父级 Callout 内部，不能单独使用。二级 Callout 内的正文、公式、图片、HTML、空行都必须带 `> >` 前缀。

非例题内容只有在形成明确的“问题 / 探究 / 观察 / 尝试 → 回答 / 推导 / 规律 / 结论”结构时，才使用二层 Callout。判断依据不是是否出现“总结、归纳、结论”等字样，而是内容功能是否形成前后对应关系。

#### 2.4.3 例题 Callout

例题结构：

```markdown
> [!example]- 例题 1
> 题干内容
>
> > [!tip]- 分析
> > 分析内容
>
> > [!success]- 解
> > 解答内容
```

要求：
1. 例题题干放在 `example` Callout 内。
2. 分析放在二级 Callout 内。
3. 解、证明、解析放在二级 Callout 内。
4. 二级 Callout 每一行都必须带 `> >`。
5. 二级 Callout 内的公式、图片、HTML、空行也必须带 `> >`。

#### 2.4.4 非例题内容的二层 Callout 嵌套

非例题内容只有在形成明确的“任务引导 → 回答 / 推导 / 规律”结构时，才使用二层 Callout。
判断依据不是原文是否出现“总结、归纳、结论”等字样，而是内容功能是否成对：
* 前置部分：问题、观察、探究、尝试、交流。一定是适用 `> [!question]` 的。
* 后续部分：有明显的结论性的东西，不需要有特殊字样出现。

示例：

```markdown
> [!question] 思考·交流
> 1. 请你仿照上面的方法说明 $(-2) \times (-5) = 10$。
> 2. 再写一些算式进行计算。你能发现什么规律？与同伴进行交流。
> > [!abstract] [[有理数乘法法则]]（multiplication)
> > 两数相乘，同号得正，异号得负，并把绝对值相乘。
> > 任何数与 $0$ 相乘，积仍为 $0$。
```

### 2.5 图片处理规则

#### 2.5.1 图片路径

不得修改：
1. 文件名。
2. 文件夹名。
3. 路径。
所有图片修改嵌入形式，默认<img src="图片路径"/>。

#### 2.5.2 多图并排

以下图片可以并排：
1. 同一道题的多个子图。
2. 同一图形变化过程。
3. 同一概念的对比图。
4. 连续编号图片。
5. 同一图号下的多张图片。

#### 2.5.3 单图居中

优先处理多图并排。
单图可以改为：

```markdown
<div align="center">
  <img src="图片路径" width="55%" />
  <br />
  图号或题注
</div>
```

#### 2.5.4 图片题注

1. 题注必须紧跟图片。
2. 图号必须紧跟对应图片。
3. 子图编号如 `(1)`、`(2)`、`甲`、`乙`、`①`、`②` 必须保留。
4. 图片属于 Callout 时，图片和题注都放入 Callout 内。

### 2.6 表格处理规则

#### 2.6.1 Markdown 表格

简单数据表使用 Markdown 表格。

#### 2.6.2 HTML 表格

以下情况使用 HTML 表格：
1. 有合并单元格。
2. 表格中有图片。
3. 表格中有多行公式。
4. Markdown 表格无法正确渲染。
5. 多图并排需要统一宽度和对齐。

#### 2.6.3 嵌套表格

如果表格属于某道题、某个列表项或某段缩进内容，表格也要缩进。
表格属于 Callout 也要纳入 Callout 中。

### 2.7 推理、证明、解题过程

将过程中的空行删除，让其紧凑。

#### 2.7.1 保留推理链

1. 保留每一步条件。
2. 保留每一步结论。
3. 保留每一步理由。
4. 不删除中间推理。
5. 不把证明缩写成结论。

#### 2.7.2 分析与解答分开

以下内容要分开：
1. 分析。
2. 解。
3. 证明。
4. 解析。
5. 结论。

如果在例题中出现，使用二级 Callout。

### 2.8 脚注处理

#### 2.8.1 转换格式

正文脚注：

```markdown
《九章算术》①
```

改为：

```markdown
《九章算术》[^1]
```

底部脚注：

```markdown
①《九章算术》
```

改为：

```markdown
[^1]: 《九章算术》
```
