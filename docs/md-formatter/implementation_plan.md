# Refactor Markdown Formatter Scripts

将目前您手写的两个独立的格式修改脚本（`格式修改(习题特调).py` 和 `格式修改(教科书特调).py`）重构为一个**企业级的、高可靠性的、高性能的 Markdown 后处理程序**。

## 存在的问题与优化方向

目前的脚本虽然能解决具体问题，但距离“企业级”有以下提升空间：
1. **性能瓶颈**：使用了数十个原生的 `re.sub` 字符串正则查找。在企业级处理中，每次匹配都重新编译正则会极大地拖慢长文档（如数百页 PDF 的 Markdown）的处理速度。应当升级为 `re.compile` 的预编译模式。
2. **缺乏架构复用**：两个文件中有大量重复的基础替换逻辑（如粗体删除、公式符号修正等），缺乏面向对象的继承设计。
3. **交互方式陈旧**：使用了 `input()` 阻塞式交互，这导致它无法与我们刚刚写好的 `mineru_apps` 批处理自动化流水线完美串联。应当改造成支持 `--mode textbook` 和 `--dir /path/` 的现代化 CLI 命令。
4. **容错与监控不足**：缺乏标准化的 `logging` 模块，如果某个特殊的文档正则匹配导致死循环或内存溢出，没有完备的日志和异常捕获机制进行定界。

## Proposed Changes

我们将新建一个独立的模块 `md_formatter`，采用**面向对象（OOP）**和**策略模式**进行重构。

### [NEW] `md_formatter/` (模块目录)

#### [NEW] `md_formatter/cli.py`
程序的命令行入口，使用 `argparse` 处理参数输入。
- 支持 `--dir` 指定目录。
- 支持 `--mode` 指定模式（`textbook` 或 `exercise`）。
- 支持 `--backup` 是否在修改前备份原文件。

#### [NEW] `md_formatter/formatters.py`
定义格式化器类架构：
- `BaseFormatter`：包含所有共用的正则表达式预编译对象，以及基础的替换方法（如去除 `**`、修正 `\mathrm`、公式替换等）。
- `TextbookFormatter(BaseFormatter)`：继承基类，包含 `教科书特调` 专属的图表融合、题注修正、标题层级修正等高级功能。
- `ExerciseFormatter(BaseFormatter)`：继承基类，包含 `习题特调` 专属的格式修正。

#### [NEW] `md_formatter/logger.py`
企业级日志配置，支持输出到控制台和 `formatter.log` 文件。

### [DELETE] 旧脚本
- `格式修改(习题特调).py`
- `格式修改(教科书特调).py`
