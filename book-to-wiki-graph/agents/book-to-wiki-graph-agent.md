# Book to Wiki Graph Agent

本 Agent 不限定学科、出版社、版本、章节数量或组织深度。旧版 `Book to
Obsidian Wiki Graph` 保持独立，不复用其中针对某本教材的层级规则。

## 最终目标

整本书只生成两类 Markdown：

- `组织层/`：以印刷目录为核心、深度开放的直属所有权树。组织笔记正文不
  重复自身标题；按原书顺序写直属子节点，并在每个组织子节点链接前写它的
  全局目录深度标题：顶层用 `#`、第二层用 `##`、第三层用 `###`，依次
  类推。这样任一章、节笔记都可单独打开并完整充当目录。
  直接链接原子的末级组织不加标题，只写原子嵌入；它以清晰名称直接保存
  在父目录中，不创建单文件文件夹。组织笔记正文不重复自己的文件名或标题。
- `原子层/`：知识点、例题、习题、情景引入四类主原子，以及从知识原文
  派生的概念卡、公式卡。主原子负责无重叠源覆盖；派生卡复制来源主原子内
  最小连续原文，不参与覆盖统计。原子
  无子节点、无指向其他笔记的链接，正文不保留任何 Markdown 标题，只保留
  属于原文的教学正文与本地资源嵌入。文件名使用数字加类别字母的编号，如
  `0001-K.md`，且编号在每个目标文件夹内独立递增，不使用内容标题。

组织节点可以同时拥有组织子节点和原子，必须服从 `children` 的混合书序。
通常最底层组织节点才链接原子，但不得为了套固定层数而虚构组织节点。

每一个组织 Markdown（包括概念索引、公式索引）都必须带 Obsidian 属性：
`organizer_key`、直属上级组织的名称/稳定键/文件路径（书籍根节点明确写
`null`）、来源文件、来源摘要、全局 `organizer_level`、从书籍到自身的完整
`hierarchy_path`、原文标题范围与最早来源位置、`root/branch/mixed/leaf`
结构角色、直属组织数、直属原子数、后代原子数、更新时间和审核状态。
属性只放在 YAML frontmatter，不改变组织笔记的标题层级与嵌入书序。

## 必须执行的流程

1. 冻结 PDF 或 Markdown 来源及摘要。PDF 默认使用 `convert_pdf.py`
   调用 MinerU；允许用其他 PDF 工具辅助核查，但必须保留可审计的页序、
   公式、表格、图片和资源路径。
2. 从印刷目录建立开放深度组织树，再进行组织层语义复核：目录中的章、节
   保留为结构组织；节内按可复用的大知识主题建立“小知识点组织层”；
   “观察·思考、思考·交流、尝试·思考、操作·交流”等教学活动标签必须随
   问题正文进入原子层，不能仅因 MinerU 输出为标题就成为组织节点；标签
   文字不得丢失，模型必须明确分类为情景、思考题、习题，或记录与知识点
   合并的理由。每节的
   直属顺序固定为“节级导语（若有）→ 独立知识主题 → 节末正式习题集”；回答
   范围覆盖多个同级知识主题的承前问题是直属 `section-introduction`，不能吞入
   第一个知识点。课中练习下沉到前一或明确对应的知识主题，只有节末正式习题
   集保留为节的直属组织节点。相邻定义若依赖角色和复用边界不同仍须拆开。用 `refine_organizers.py`
   应用摘要绑定的审核清单，模型不得擅自改变审核后的所有权。新模式没有通过
   组织层审核就不得原子化或物化；任何新建主题的后代范围不得越过下一个保留
   的印刷标题，非练习性质的印刷小节也不得只剩练习。一个知识主题的引导问题
   位于自身印刷标题之前时，允许同一印刷组织节点拥有标题前、标题后两个连续
   来源段，模型任务在该标题处断开。
3. 运行 `atomize_book.py prepare`，把每个组织节点的直属正文封装为带摘要的
   连续源行任务。
4. 第一轮由当前 Agent 默认完成语义划分；也可以在用户明确选择时使用
   `run_atomization_model.py --model ... --execute`。决定只写连续行范围、
   类别、标题、边界理由、教学凝聚理由和置信度，不得重写正文。
   在分类感知模式中，知识点数量与边界完全由 LLM 根据教学语义决定；基线
   原子仅作覆盖上下文提示，不能机械继承。无转接词的并列正式定义仍须拆分，
   例如“全称量词”和“存在量词”必须是两个独立可复用知识点。
5. 运行 `validate-round1`，再运行 `prepare-audit`。第二轮逐一审核所有相邻
   原子，给出 `keep`、`merge` 或 `resegment`，并返回完整连续分区。
6. 运行 `finalize`。`atomization-review-queue.json` 未清零时必须停止，不能
   物化。
   修复已经物化的旧书库时，如果旧终审清单把同一全书/章/节导语拆成段落、
   图片或“续 2”等多个原子，不得只改组织 Markdown。当前 Agent 先核对完整
   连续源范围，再运行 `migrate_scoped_introductions.py` 同步重绑原子化清单、
   关系清单和冗余无标题导语包装层，随后在暂存目录重新物化；片段间出现非空
   未覆盖正文、跨结构标题或所有者不一致时迁移必须停止并回到组织层审核。
   如果重新物化后暴露出旧版“印刷小节只剩练习”或印刷练习分组跨越下一同级
   节点，不得关闭校验。使用 `migrate_legacy_organizer_ownership.py`，只允许把
   已审核的无标题教学主题嵌入正确印刷小节，或创建原文明示的练习分组；所有
   原子范围、类别、正文和语义关系保持不变，归属键、组织笔记路径和摘要同步
   重绑。
7. 新模式把教学角色审核并入前两轮：同一次决定必须给出每个知识原子的
   `teaches/assumes/outputs`、局部关系和概念/公式派生候选。旧版
   `prepare-role-review` 只用于兼容 `llm-two-pass` 清单。
8. Markdown 物化前调用插件内独立 Skill `$knowledge-relation-mapper`，对审核后
   的基础清单使用 `prepare-concepts --atomization-final`。第一轮把稳定虚拟原子
   当作不可改写的 TextUnit，提取全书规范概念、别名、定义和
   原子—概念教学角色；练习只能映射已有概念，不能凭题干新建概念。
9. 第二轮用原书邻近、组织区域、显式指代、全文词法、可选向量、已有图二跳
   和跨章复现召回候选，逐一判断正向、反向或无关系，并以 `0.97` 门槛处理
   同义概念合并。第三轮用 WCC、DAG、反向先修、传递冗余和孤点规则审计
   全图；真正承载可复用数学思想或方法的例题标为 `bridge`。只有异常项进入
   人工队列。全图若证明知识边界错误，可返回 `merge/split/resegment`；最多
   自动回流两次，每次边界变化都使受影响章节和跨章摘要失效。
10. 只有原子化和关系终审同时通过且队列清零，才能用
    `materialize_book.py --relation-final` 一次写出主原子、派生卡、索引和图谱。
    概念卡以规范概念名命名，重名时增加稳定短后缀；公式卡使用
    `NNNN-F.md`。按章建立不进 Canvas
    的概念索引和公式索引。
11. 校验书库，生成全书图、章节核心图和小节细图；构建器为每一张 Canvas
    生成同名 PNG。运行 `canvas_review.py prepare`，由当前 Agent 用图像查看器
    打开并查看每张 PNG，优先评价知识逻辑完整性、关系方向、孤点和端口，再评价美观与密度；
    `canvas_review.py finalize` 通过后，用 `--canvas-index --canvas-review`
    校验整套结果。

Canvas 评价决策必须绑定 `canvas_sha256` 与 `png_sha256`，并分别给出
`logic.score`、`visual.score`、图片观察、缺失/反向关系、孤点、端口问题和
优化动作。逻辑评分低于阈值时先回到关系或布局重建，不能用改颜色、加装饰边
掩盖逻辑缺口；最多执行配置的两轮优化。

## 完整教学单元规则

- 知识点以完整教学语义为边界：定义、条件、符号、解释、推导和紧邻结论
  应共同存在。只有两侧都能独立命名、理解和复用时才切分。
- 知识点切割由 LLM 独占决定；确定性程序不得按空行、段落长度或活动标题
  自动决定数量。复合小节标题只是召回提示，不是合并理由。
- 保留“观察、思考、尝试、交流、探究”等原文活动标记。完整问题默认作为
  情景/思考题；只有与紧邻定义不可分割时才并入知识点，并记录
  `merged-with-knowledge` 理由。原子正文把标记作为普通原文行保留，不因
  去除 Markdown 标题而消失。
- 明确承接已学知识并提出一个不同的新主题的短引导可以独立成为
  `knowledge-motivation`，但必须在关系审核中形成“已有知识 → 引导 → 新知识”
  的证据链；只服务于紧邻解释的课堂提示仍并入知识点。
- 情景引入先按作用域判断：全书前言或读者导读使用
  `book-introduction`，章导语使用 `chapter-introduction`，统领多个同级主题
  的节导语使用 `section-introduction`，只引出一个知识主题的完整问题、例子
  或现实背景使用 `knowledge-motivation`。全书/章/节导语在同一上级和角色下
  必须是一个完整原子，连续的段落、问题、插图和图注一直保留到下一个结构
  标题；禁止生成“续 2”、`part 2` 或只有图片的导语碎片。
- 知识点情景必须保留完整的问题背景、图/图注和最后的提问，并与它引出的
  知识点一起审核逻辑关系。空行、分页和图片位置不能成为拆分理由。
- 学完知识后要求比较、综合、延伸或开放探究的完整问题是例外：保留为
  `category: scenario`、`scenario_role: reflection-question`，独立写入
  `原子层/思考题/NNNN-T.md`。它不是例题或常规习题；关系分析中把它当作
  可由已学知识引发、并可继续引出后续或课外知识的情景节点。
- 同一主题组织层可以链接多个可独立复用的知识原子；例如“集合的表达方式”
  应分别链接“列举法”和“描述法”，不能因共享主题而强行合并。
- 回答范围覆盖多个同级知识主题的短承前问题属于节级导语，必须作为该节第一
  个直属情景原子；只服务于一个紧邻说明的问题才并入该知识原子。例如“集合
  是否也有类似运算”应置于本节最前，而并集、交集、全集、补集各自保持独立。
- 课中“练习”归入它实际巩固的知识主题；只有节末正式“习题 X.X”作为该节
  最后的直属组织入口。
- 例题必须保留完整题干、分析、解答和紧邻结论；习题必须保留顶层题目、
  全部小问、图表和材料。
- 目录所有权、排除范围、显式例题起点和顶层习题题号是硬边界；空行、
  图片、公式、框内结论和普通活动标题只是软边界。
- 少于 150 个规范化字符或只有一条非空行的知识点必须进入碎片审计。
  只有正式定义、定理或法则在给出具体独立性理由且置信度不低于 0.95 时
  才能单独保留。
- 每个原子都必须写入 `atom_key`、`owner_key`、来源 PDF、来源摘要、源行
  范围、全部所属组织层、更新时间、审核状态、预计学习时间、难度、重要度
  和学习目标。知识点还必须包含前置知识与关键词；例题、习题、情景、概念
  和公式分别补充完整解答、题目范围、情景角色或派生来源属性。
- 概念卡只能保留正式定义句及其紧邻条件、符号或公式，不能混入举例、活动
  提示或问题。文件直接使用规范概念名；只有真正重名时才加稳定短后缀。

## 关系与 Canvas 原则

图谱包含“原子 + 规范概念”两层。概念关系只使用先修、发展、推导、上位、
组成、对比和类比；兼容 Canvas 的原子投影使用先修、发展、推导、引发、例证、应用、练习、
对比或类比。有向边始终沿学习过程前进。“已学知识引发一个新问题，再导向
新知识”应表示为 `已有知识 → 引发 → 情景 → 引发 → 新知识`。显式关系与
教学推断分开记录；推断必须引用两端原文且置信度不低于 `0.95`。主线只由
知识点和情景组成，并且无环；尽量不保留孤立知识点。例题和习题应连接到
它们说明、应用或巩固的知识，只有 `bridge` 例题可进入 Canvas。

JSON 永远是权威数据；Neo4j 只可作为显式执行的查询和 WCC/Leiden 分析副本。
总图只展示书与章节，章节卡片进入章节核心图；跨章关系向上聚合为章节路线。
章节核心图以直属节为星域，展示知识、情景和精选 `bridge` 例题，不展示规范
概念节点、公式节点、任何
练习卡或练习边；每个节星域提供进入小节细图的放大入口。小节细图才加入练习
组织层 Markdown 入口，每组最多一条主归属边，并与所巩固知识放在同一局部
星域。组织层不再额外复制为与原子同名的地标；只连接一个原子的规范概念也
折叠到原子卡。确实独立且有审核理由的节点用标注为“归属”的下→上连线接入
组织入口；禁止用“书序”边伪装知识依赖。

连线必须显式使用四向端口：知识发展从右侧引出并从下一节点左侧接入；
`引发` 关系从右侧引出、从受启发节点上侧接入；例证、应用、练习包含、
对比和类比从下侧分支并从目标上侧接入。这套端口语法参考
`/Users/oven/Documents/ovenmathmap/mathmap.canvas` 的主要习惯。布局必须
稳定、无卡片重叠、知识点沿实际关系方向推进（右出节点不得落在左侧，
下出节点不得落在上方）；无关系的组织星域采用稳定二维紧凑排布，避免
强行拉成一条斜线。用嵌套 Canvas `group` 包住对应组织层节点，
适配 Obsidian 明暗主题。原子颜色仅表示类别，不修改
原子 Markdown。任一图存在多个实质节点时，知识、情景、精选例题、节入口、
练习组织入口和规范概念枢纽都不得孤立。

所有工作使用任务专属暂存目录和原子写入。没有明确授权时不得覆盖已有
书库或 Canvas。
