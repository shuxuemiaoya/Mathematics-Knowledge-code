# Book to Wiki Graph Agent

本 Agent 不限定学科、出版社、版本、章节数量或组织深度。旧版 `Book to
Obsidian Wiki Graph` 保持独立，不复用其中针对某本教材的层级规则。

## 最终目标

整本书只生成两类 Markdown：

- `组织层/`：以印刷目录为核心、深度开放的直属所有权树。组织笔记只含
  按原书顺序排列的直属子节点嵌入链接，不重复写自身标题。父组织在每个
  组织子节点链接前写与全局目录深度一致的标题：顶层用 `#`、第二层用
  `##`、第三层用 `###`，依次类推。直接链接原子的末级组织不加标题，只写
  原子嵌入；它直接保存为父目录中的编号 Markdown，不创建单文件文件夹。
- `原子层/`：知识点、例题、习题、情景引入四类最小完整教学单元。原子
  无子节点、无指向其他笔记的链接，正文不保留任何 Markdown 标题，只保留
  属于原文的教学正文与本地资源嵌入。文件名使用数字加类别字母的编号，如
  `0001-K.md`，不使用内容标题。

组织节点可以同时拥有组织子节点和原子，必须服从 `children` 的混合书序。
通常最底层组织节点才链接原子，但不得为了套固定层数而虚构组织节点。

## 必须执行的流程

1. 冻结 PDF 或 Markdown 来源及摘要。PDF 默认使用 `convert_pdf.py`
   调用 MinerU；允许用其他 PDF 工具辅助核查，但必须保留可审计的页序、
   公式、表格、图片和资源路径。
2. 从印刷目录建立开放深度组织树，再进行组织层语义复核：目录中的章、节
   保留为结构组织；节内按可复用的大知识主题建立“小知识点组织层”；
   “观察·思考、思考·交流、尝试·思考、操作·交流”等教学活动标签必须随
   问题正文进入原子层，不能仅因 MinerU 输出为标题就成为组织节点；随堂
   练习、习题及其正式分组可以保留为组织节点。用 `refine_organizers.py`
   应用摘要绑定的审核清单，模型不得擅自改变审核后的所有权。
3. 运行 `atomize_book.py prepare`，把每个组织节点的直属正文封装为带摘要的
   连续源行任务。
4. 第一轮由当前 Agent 默认完成语义划分；也可以在用户明确选择时使用
   `run_atomization_model.py --model ... --execute`。决定只写连续行范围、
   类别、标题、边界理由、教学凝聚理由和置信度，不得重写正文。
5. 运行 `validate-round1`，再运行 `prepare-audit`。第二轮逐一审核所有相邻
   原子，给出 `keep`、`merge` 或 `resegment`，并返回完整连续分区。
6. 运行 `finalize`。`atomization-review-queue.json` 未清零时必须停止，不能
   物化。
7. 用 `materialize_book.py` 从通过审核的最终清单复制原文内容、确定性移除
   原子范围内的 Markdown 标题行、调整资源路径，按紧凑组织布局生成两层
   Markdown 和带 `atomization_review` 的 `book-graph.json`。
8. Markdown 物化后必须调用插件内独立 Skill `$knowledge-relation-mapper`。
   第一轮把原子当作不可改写的 TextUnit，提取全书规范概念、别名、定义和
   原子—概念教学角色；练习只能映射已有概念，不能凭题干新建概念。
9. 第二轮用原书邻近、组织区域、显式指代、全文词法、可选向量、已有图二跳
   和跨章复现召回候选，逐一判断正向、反向或无关系，并以 `0.97` 门槛处理
   同义概念合并。第三轮用 WCC、DAG、反向先修、传递冗余和孤点规则审计
   全图；真正承载可复用数学思想或方法的例题标为 `bridge`。只有异常项进入
   人工队列；队列未清零时不得生成章节语义图。
10. 三轮 `relation-final.json` 通过后用 `apply` 生成带概念和投影关系的清单。校验书库，
    生成只含全书与章节的 `overview.canvas` 及每章一张知识星图，最后用
    `--canvas-index` 校验整套结果。

## 完整教学单元规则

- 知识点以完整教学语义为边界：定义、条件、符号、解释、推导和紧邻结论
  应共同存在。只有两侧都能独立命名、理解和复用时才切分。
- “观察、思考、尝试”等短提示与其引出的知识合并。只有完整叙事、现实
  背景、实验设置或学习动机才能独立成为情景原子。
- 例题必须保留完整题干、分析、解答和紧邻结论；习题必须保留顶层题目、
  全部小问、图表和材料。
- 目录所有权、排除范围、显式例题起点和顶层习题题号是硬边界；空行、
  图片、公式、框内结论和普通活动标题只是软边界。
- 少于 150 个规范化字符或只有一条非空行的知识点必须进入碎片审计。
  只有正式定义、定理或法则在给出具体独立性理由且置信度不低于 0.95 时
  才能单独保留。

## 关系与 Canvas 原则

图谱包含“原子 + 规范概念”两层。概念关系只使用先修、发展、推导、上位、
组成、对比和类比；兼容 Canvas 的原子投影使用先修、发展、推导、引发、例证、应用、练习、
对比或类比。有向边始终沿学习过程前进。“已学知识引发一个新问题，再导向
新知识”应表示为 `已有知识 → 引发 → 情景 → 引发 → 新知识`。显式关系与
教学推断分开记录；推断必须引用两端原文且置信度不低于 `0.95`。主线只由
知识点和情景组成，并且无环；尽量不保留孤立知识点。例题和习题应连接到
它们说明、应用或巩固的知识，只有 `bridge` 例题可进入 Canvas。

JSON 永远是权威数据；Neo4j 只可作为显式执行的查询和 WCC/Leiden 分析副本。
总图只展示书与章节，章节卡片进入对应章节知识星图；跨章原子关系向上聚合
为章节路线。章节图中的直属节是星域，更深组织节点是区内地标，不画完整
目录父子树。没有可见后代的地标不显示；每个保留地标只用一条灰色“包含”
边接向按书序最近的可见后代，以消除孤点但不恢复整棵目录树。主线知识按中心向外的学习顺序形成星座骨架，情景和精选
`bridge` 例题围绕相关核心排布。每道练习/习题原子不单独进入 Canvas，
改用其练习类组织层 Markdown 作为聚合星群；跨多个知识点的练习组可以通过
无独立 Markdown 的“综合练习汇合”节点连接。跨章端点显示为外围入口。

连线必须显式使用四向端口：知识发展从右侧引出并从下一节点左侧接入；
`引发` 关系从右侧引出、从受启发节点上侧接入；例证、应用、练习包含、
对比和类比从下侧分支并从目标上侧接入。这套端口语法参考
`/Users/oven/Documents/ovenmathmap/mathmap.canvas` 的主要习惯。布局必须
稳定、无卡片重叠、适配 Obsidian 明暗主题。原子颜色仅表示类别，不修改
原子 Markdown。章节存在多个实质节点时，知识、情景、精选例题、外章入口、
组织地标、练习星群和虚拟汇合节点都不得孤立。

所有工作使用任务专属暂存目录和原子写入。没有明确授权时不得覆盖已有
书库或 Canvas。
